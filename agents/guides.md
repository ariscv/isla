## V 扩展符号执行约束原则

不要为了让 solve-state 快速通过而把cli flag或者运行上下文简单地设置成单一代表值。`vl`、`vstart`、`vtype`、mask/tail policy、寄存器选择等都属于程序运行态，除非用户明确要求生成某个特定上下文，否则不能在 Isla 入口层覆盖成固定值。

可以固化真实 RISC-V 处理器不可变的编译/配置参数，例如 `vlen`、`elen`、`xlen`，以及由这些参数决定的静态上界。此类参数来自 Sail config 或目标配置，本来就不是每条 path 上变化的程序上下文。

应优先加强 Sail/RISC-V 语义中已有但模型表达过松的约束，例如：
- `SEW` 只能是 8/16/32/64，`LMUL_pow` 只能是 -3..3 且排除保留编码；
- `num_elem` 只能落在 `vlen` 和合法 SEW/LMUL 推导出的有限集合中；
- vector crypto 的 `vl`/`vstart` element-group 对齐、`EGW <= LMUL * VLEN`、寄存器组不重叠等 encdec 条件；
- 访存、CSR、寄存器组等路径如果是非法状态，应通过原模型的 `Illegal_Instruction`、`assert` 或已有检查丢弃，而不是替换成任意合法代表值。

需要限制的是两类路径规模：
- 符号执行可能无限 fork 或无法停机的路径，例如未受约束的循环边界、动态宽度导致的无限候选、递归/回边没有可证明上界；
- Sail 模型约束过松导致的不必要 fork，例如明知只有有限合法编码却让 solver 在更大整数域上枚举。

如果 timeout 来自有限上下文的笛卡尔积，而不是无限 fork 或错误建模，应先估算规模再处理。V 扩展常见规模来自 `SEW * LMUL * vstart/vl * mask/tail * 32 个 vreg 分组` 的组合；当这些组合都是真实合法状态时，可以在合理范围内调高单 clause 或全量 solve timeout，而不是把上下文固定成单点。调整阈值前应先看 itrace 中的具体停点：如果停在固定上界的 vector crypto element group 写回等路径，属于可控规模；如果停在无法证明上界的循环、递归或动态宽度候选，则应先补语义约束或改执行策略。

## 有 Z3 与无 Z3 共用一套合并逻辑（2026-11-18 用户确认）

无 SMT 模式不是另一套实现，而是"关掉 Z3 求解"的同一套逻辑。新增或修改路径合并/区域/臂处理时：

- 判定统一走一个分层的判定接口：先做不依赖求解器的结构判定（常量折叠、`structural_bool`、具体值），能确定就直接得出"死/活"；确定不了再交给 Z3（仅在开启时），无 SMT 时该层固定返回 Unknown。
- 对判定结果的后续处理（删除死臂、保留为带完整守卫的叶子、合并、标认证状态）只写一份；有 Z3 和无 Z3 的差别只体现在判定接口的实现，以及结果的认证标记（有 Z3 判出的可认证，无 Z3 的 Unknown 标 uncertified）。
- 不得写成"if no_smt { 一套 } else { 另一套 }"的分叉逻辑；需要按模式分叉时，先考虑能否改成判定层的差异。
- 评审时核对：新增的 `no_smt` / `skip_*` 判断只应出现在判定与认证标记处，不应出现在合并、区域、事件处理的主流程里。

## 探索限制一律默认不限制（2026-11-18 用户多次强调）

符号执行与 path merge 的**探索类限制**（区域步数预算、嵌套深度、片段数上限、`max_forks_per_branch`/`max_forks_per_path`/`max_backjumps_per_loop`/`max_path_depth`/`max_fork_pct_*`、`on_limit_reached` 截断、有限域大小上限、循环/回跳计数等）**默认全部不设**；可以提供配置项，但缺省必须是无限。只保留与 Isla 符号执行无关的**外层硬限制**（时间、内存）。目标是 path merge 之后尽量完整地把信息带进 DAG。Workaround 配置里的执行限制条目一律关闭或注释。**默认忽略寄存器与变量的读写次序**（TOML/flag 可配置，缺省忽略），以便合并。评审时核对：新增代码不得引入默认非零的探索上限。

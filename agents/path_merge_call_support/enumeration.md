# E1：合并路径终态枚举

> **注意（ATTENTION）：合并路径的内存读取为并集语义；需要精确内存读序列时不可信。**
> 这是 F4 按用户指定放宽的项目内使用范围。主迹保留两臂所有 ReadMem；寄存器读也仍取并集。
> 仅适用于 RAM 与已核实的顺序数组内存回调；设备 Custom 与任意 Constrained 生成器区域保守拒绝。
> 不支持未经审计、会通过内部可变状态执行 IO 或改变内存的读回调。新增此类回调必须先重新核实。

F4 保留完整带条件内存读记录；枚举不改变主迹。每个解导出样本时用该解的 guard 选择真实发生的读，再按既有首次触碰规则构造内存。仅浏览旧主迹或原 isarch JSON 的访存并集不能恢复逐路径读序列。具体保护条件与事件见 [合并记录](merge-record.md)，样本协议及写后再读限制见 [样本说明](samples.md)。


合并路径在自己的求解器仍存活时进行两级投影枚举。一级按带上下文的守卫分出原始分叉叶子；二级在叶子内用深度优先分裂枚举实际被守卫测试的位片段组合。核心不包含 ISA 字段名、页表格式或页表遍历解码。

## 配置与入口

在 `--execution-limits-config` 指定的独立 TOML 中添加：

```toml
[execution_limits.merge_enumeration]
enabled = true
mode = "samples"
class_cap = 1024
path_cap = 65536
sample_stride = 1
enumeration_threads = 16
```

六个字段均可省略，前五项默认分别为 `false`、`"samples"`、`1024`、`65536`、`1`；`enumeration_threads` 默认 `min(16, std::thread::available_parallelism())`，与 `-T` 的执行线程数独立。`mode` 只接受 `"samples"` 与 `"count"`。上限必须是正整数；未知字段、错误类型、零和负数会在加载时拒绝。`execution_limits.enabled=false` 仍沿用原有规则，不能同时配置其他限制字段。枚举开关与合并开关独立；还需用 `--path-merging` 或 `merge_policy` 开启希望合并的区域。

`sample_stride = N` 只在 samples 模式选择导出位置。每条完成路径按规范守卫类顺序、类内 DFS 顺序分配解序号，从 **0** 开始，序号满足 `ordinal % N == 0` 时物化完整代表模型并调用样本消费者；其余位置只读守卫与被测位的投影见证、计数和维护 DFS 前沿，不求值完整输入、返回值或处理器状态。`class_cap=1` 时这就是每隔 N 个守卫类保留一个。类内有多个解时，序号跨类连续，不在每个类重置；不同完成路径各自从 0 开始。因此样本数是各路径 `ceil(counted_paths/N)` 的和，并非全局总数除 N 后取整。`N=1` 仍导出每个已访问解；count 模式无论 stride 是多少都不物化样本。

这属于 **规范守卫顺序与类内 DFS 顺序的等间隔系统抽样，不是随机抽样**。类内 DFS 顺序与被测字段位及求解器见证有关，周期可能与字段位相关；某些形状可能集中出现或被遗漏。每条路径从 0 重置也使短路径获得较高的保留比例。样本占比不能直接称为真实状态概率，Sv39 上测得的偏差也不能作为 Sv48 偏差的上界。

为使 stride 选择不改变后续代表值，samples 模式复用既有事件重放和增量 SAT 接口，将 DFS 投影与完整样本物化放在隔离的 Context 中；只为被选中的解重放原约束及当前类／片段条件。枚举专用求解器固定种子为 0，普通执行的随机种子策略不变。旧实现的具体代表值本就不保证跨运行稳定；`N=1` 保留全量导出、上限与样本 v1 字段语义，但具体代表值和 DFS 发现顺序可能与旧二进制不同。未测试的位仍取一个满足原约束的代表值，没有为抽样固定 ISA 状态或缩小可行域。

`mode = "count"` 只统计两级投影域。它复用守卫树前序、父链上下文和去重的被测位，一级按规范布尔顺序 DFS，二级沿用模型引导的片段 DFS，以 SAT 假设查询剪去不可满足的前缀。计数前先在原路径条件和活动上下文中检查守卫两种极性，跳过只有一种可行极性的分裂。每个 SAT 见证只读取打包的守卫真值与被测位，不查询完整输入符号、返回值或处理器状态，不物化代表样本，也不调用样本消费者。即使设置 `ISLA_EXPORT_SAMPLES`，也不会导出这些枚举样本。原有每条合并路径的普通 ISA 输出仍沿用既有物化流程。

计数结果仍写入每条路径的 `merge_enumeration`，包含 `schema_version=2`、`mode="count"`、`class_cap`、`path_cap`、`counted_classes`（已访问的可行守卫叶子类数）、`counted_paths`（按上限计入的片段组合数）、`truncated_classes`（确有剩余解的已访问类数）和 `path_truncated`。不输出 `guard_classes`、代表样本或 `enumerated_total`，避免将计数误当作已导出样本数。类内上限仍按片段组合数计，不限制访问的守卫类数；只有额外 SAT 查询证明确有剩余解或可行类时才标记截断。`path_truncated=false` 但 `truncated_classes>0` 表示类数完整，片段组合数受类内上限限制。

启用 `ISLA_STATS=1` 后，`MERGE_STATS` 及周期快照的 `merge_enumeration` 汇总计数模式的 `completed_paths`、`counted_classes`、`counted_paths`、`truncated_classes`、`truncated_paths`。常规入口在分区进度中报告类数、解数与墙钟时间；较大分区每 4096 类还报告 SAT 次数、SAT 累计耗时和投影见证累计耗时。显式分量诊断仍保留原有计数汇总行。两种模式都汇总 `sample_stride` 和 `exported_samples`，samples 模式也汇总全部已访问类与解数；以下字段表描述 samples 模式。sample v1 行没有增加或改写协议字段。

isarch 将结果放在每个路径 item 的 `merge_enumeration` 字段中。`isla-execute-function` 在该路径的 `Result:` 后输出单行 `merge_enumeration: {JSON}`，`--tree` 模式也保留此行。没有开启枚举时不查询模型、不扫描枚举依赖、不输出字段或附加行。旧 JSON 反序列化时缺少此字段仍有效。

正常完成的处理器结果都参与枚举，包括 fault、page fault、access fault、非法指令等构造子。被路径条件排除、`Run::Dead`、执行器错误或未完成的路径不是正常处理器结果，不作为可行解输出。求解器返回 Unknown 或错误时明确报错，不替换成代表值，也不把它当作完整枚举或 UNSAT。

## 前置核实

| 核实项 | 结论与源码证据 |
| --- | --- |
| (a) 记录归属与回滚 | 原实现已经将记录保存在 `executor/frame.rs` 的 `Frame/LocalFrame.region_merge_records` 中；`freeze_frame`、`unfreeze_frame`、`new_call` 都复制历史。`region_merge.rs` 的 `execute_region` 在克隆帧中推演，`merge_states` 只拼接成功臂的新记录，最后才替换原帧。拒绝不替换原帧，求解器保存点同步回滚。记录不是按 task_id 收集的全局列表。E1 增加稳定编号和父子上下文，并让 isarch 的 ExecuteAs 检查点续执行同时携带帧内合并历史及纯定义区间。 |
| (b) DefineConst 与阻断 | `smt.rs` 的 `add_internal(DefineConst)` 将表达式翻译、化简后存入 `decls`；`Model::get_exp/get_var` 复用该 AST，`Assert` 也经同一符号表翻译。F5 按位分裂 `Extract(hi, lo, Var(symbol))`，模型中的片段值从完整符号取值本地截取；符号可以是派生定义。派生 XOR 符号的两位片段测试得到四个组合，证明没有把 DefineConst 当成自由声明或只枚举守卫真值。不修改求解器 API。 |
| (c) 输出位置 | `src/isarch/exec.rs` 的完成路径 collector 在取得路径模型后物化 `AssemGenJsonItem`；E1 在释放该模型借用后、求解器销毁前调用枚举，并将结果写入可省略字段。代表状态继续沿用既有物化代码。函数入口在 `model_collector` 中枚举后入队，沿用既有输出队列。 |

`ISLA_MERGE_RECORDS` 仍是合并提交时的独立 JSON Lines 观测输出，不是最终路径清单。E1 将其记录格式版本升级为 **2**：`record_id` 在推演前分配，新增 `parent_record` 和 `arm`。回滚尝试消耗的编号可以留下空洞，但不会留下记录；继承记录保持原编号。未启用枚举时，普通路径输出保持不变；显式开启旧记录日志时，该日志按新的记录协议输出上下文。

## 枚举结果字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 整数 | 枚举格式当前为 `2`，与独立记录日志的版本区分 |
| `class_cap` / `path_cap` | 整数 | 本次实际使用的类内解数上限／路径总解数上限 |
| `guard_records` | 数组 | 本路径保存的全部合并记录，包括嵌套记录 |
| `tested_slices` | 数组 | 本路径全部守卫测试的片段表，只保存一次，保留记录归属 |
| `guard_classes` | 数组 | 至少导出一个解的可行叶子类；stride>1 时是稀疏数组，不能用 class_id 直接当数组下标 |
| `enumerated_total` / `exported_samples` | 整数 | 已物化并交给消费者的解数，等于所有保留类的 `solution_count` 之和；配置样本文件时对应实际导出行数 |
| `sample_stride` | 整数 | 实际使用的正整数采样步长 |
| `counted_classes` / `counted_paths` | 整数 | 全部已访问的可行守卫类数／计入预算的投影解数，包含未导出位置 |
| `truncated_classes` | 整数 | 全部已访问类中确有未计入解的类数，包含未导出的类 |
| `path_truncated` | 布尔 | 路径总上限阻止了尚存的可行解或后续叶子类输出 |

`guard_records` 每项包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `record_id` | 整数 | 本进程唯一、随帧继承的合并记录编号，不是 SMT 符号编号 |
| `parent_record` | 整数或 null | 外层记录编号；根为 null |
| `arm` | 字符串 | 该记录位于父记录的 `then` / `else` 臂；根为 `root` |
| `condition` | 对象 | `symbol` 为迹中的 `vN`，`smt_id` 为变量号 |
| `function` / `branch_pc` | 字符串／整数 | Sail 解码函数名与原 IR 分支位置 |
| `source_loc` | 对象 | 原始 `file/line1/char1/line2/char2`，不伪造未知位置 |

`guard_classes` 每项包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `class_id` | 整数 | 此路径内规范守卫位串的字典序编号，从 0 开始；固定事件迹和预算下与线程数无关 |
| `guard_assignment` | 对象 | 记录编号字符串 → **上下文与守卫合取的布尔值**；上下文不成立的记录规范化为 false，不声称其裸守卫为 false |
| `solutions` | 数组 | 满足该类和真实路径条件的片段组合，每个组合只输出一个代表模型 |
| `solution_count` | 整数 | 已输出的 `solutions` 数量，不是估算的完整域大小 |
| `truncated` | 布尔 | 类上限或路径总上限阻止了本类尚存解的输出 |

每个 `tested_slices` 项包含 `symbol`（`vN`）、`smt_id`、`hi`、`lo`、`source_loc`、`record_id`。位下标沿用 SMT Extract 的闭区间语义。源码位置来自对应定义事件；原始 IR 标为未知时保留未知位置。沿定义追踪别名，并折叠连续的 Extract；一般派生计算保留其符号，使用其真实 AST。相同片段被不同守卫引用时保留各自的记录归属，可能重复出现在数组中，但分裂用的位集合会去重，不会重复计算组合。

每个解包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `slice_values` | 字符串数组 | 与 `tested_slices` 按下标对应的定宽 `#b…` 值，最高位在左 |
| `representative.result` | 字符串 | 在这个解的模型下物化的函数／处理器返回值 |

顶层原有 `isa-state`、访存等字段仍代表原路径选出的一个模型；本次没有为每个解复制这些 ISA 输出。每解保留自己的返回结果和片段值；完整输入由 samples v1 文件承载。完整 SMT 定义仍来自对应路径迹；仅凭进程外另一条路径的同号 `vN` 不能解释本结果。

## 算法与上限语义

1. 从终态帧取记录，检查编号唯一、父链完整且无环。沿父链计算 `ctx(root)=true`，子上下文是父上下文与父守卫对应极性的合取。按照守卫树前序排序，父记录及其子树先于下一棵树；JSON 中记录和片段的顺序仍沿用原帧顺序。
2. 一级类的定义仍是 `p_r = ctx_r ∧ g_r`。DFS 栈保存待访问的分支前缀和已固定的守卫位置；复用 `check_sat_with` 检查前缀，UNSAT 时整支剪去，Unknown/错误直接返回错误。并行常规入口按 false/true 顺序展开活动分裂守卫，使每分区访问的类为规范前缀；计数阶段每分区最多访问 path_cap 个解。不能先遍历全部可行类再处理很小的预算。
3. 每次一次性读取打包的裸守卫真值，再沿父链规范化：上下文不成立的记录直接赋 false；活动上下文中 `ctx∧g` 等于裸 `g`。固定极性与不活动守卫不产生额外分裂。原来的模型引导一级 DFS 仍保存在显式分量诊断入口；它不能在任意发现顺序上提前截断后同时保证规范预算前缀，因此常规入口采用上述规范一级前缀遍历。全部工作线程使用同一遍历逻辑。
4. 二级仍使用整条路径全部守卫测试过的片段并集；跨类只扫描一次。对去重的实际位同样做模型引导的 DFS：模型选中的位分支直接走到叶子，相反分支进入前沿，随后在当前守卫类和真实路径条件下剪枝。字段耦合仍由 Z3 保留，例如 `¬(W∧¬R)` 只产生三个组合。一般派生表达式沿用原 AST，不把它当成自由输入。
5. 一级 Sat 模型提供第一个二级解的投影见证。被 stride 选中时，在隔离求解器中用原约束和当前投影条件物化代表样本；完整输入符号每个只求值一次，所有重复、重叠片段均本地截取。到达类上限时，将剩余 DFS 前沿因式分解后作一次存在性查询；存在未输出解才标记截断，不再抽取额外模型。
6. 求解器中不增加逐类或逐解阻断断言；前沿的大小只与守卫数、被测位数有关，不随已输出类数增长。外层仍使用一个保存点保护模型缓存等状态，正常或错误返回都配对回滚。旧阻断算法仅保存在测试模块中作为独立参照。

完整样本只在 stride 选中的解上物化。访存导出每个事件只查询一次提交条件、基址、完整数据，再本地拆字节；8 字节事件的 `Model::get_exp` 从 24 次降为 3 次。未改写的后态寄存器复用同一模型的前态物化结果，`isa_state` 通过现有 FmtVal 复用已物化的前态，避免再次求值。逐字节参照与旧 ISA 格式化的字节比较覆盖带条件读、宽位向量及地址回绕。

上限按**已访问的投影解数**计数，stride 不改变预算。达到数值后额外查询一次：只有确有未计入预算的可行解才设置截断，刚好完整时保持 false。类上限触发后仍尝试其他类；因此类 `truncated=true` 可以与 `path_truncated=false` 同时出现。路径上限触发后可能仍有未发现的类，不能把当前类数当作完整叶子数。类没有片段时每类只消耗一个解的预算。

F8 起类顺序为守卫树前序下规范赋值位串的字典序（false 在前）；类内仍使用模型引导的片段 DFS。固定配置、相同事件和枚举版本下，采样与全量使用相同投影和代表值选择；不同版本、tactic 或约束下不保证相同；编号在进程内唯一，不保证跨运行稳定。上限生效时不声称得到均匀样本，也不声称完整覆盖。完整性须同时检查 `path_truncated=false` 和汇总 `truncated_classes=0`。stride 跳过本身不会设置 truncated；stride>1 时即使两个截断标志均为零，样本集合仍只是子集。这里的完整性只指选定守卫和片段的投影域；若未被守卫测试的位会影响返回值，一个代表结果不等于穷举了全部可能返回值。

## 适用范围与验收

**寄存器读取采用并集语义。** 只在一臂读取的寄存器，在合并路径主迹上也视为读过。枚举恢复叶子输入和返回结果，不恢复逐条精确寄存器读写顺序、事件因果关系或每臂精确迹。需要这些信息时仍须实现全消费方的 guarded events。含内存访问或被调函数写状态的区域继续按既有规则拒绝合并。RISC-V 字段名映射与页表遍历解码留给 `agents/` 下的薄后处理层；不应写入 isla-lib。

函数级真实 IR 验证沿用 `baseline_config_const.toml`：分叉 **10** 条、合并 **1** 条，一级恢复 **10** 类；默认上限与实际不限额（测试中将两上限设为 `usize::MAX`）均输出 **256** 个二级解，无截断。`class_cap=2/path_cap=5` 输出 **3** 类、**5** 解，路径截断为 true。每个输出解均在原路径 Z3 求解器上复核片段约束。该函数末尾关于 reserved 的直接返回表达式未形成分叉守卫，因此其位保留代表值；这与原始叶子中存在符号返回值一致。

### 求解量与预估收益

按原约束图严格分解仍为一个分量，预计求解量**不下降**。本轮现行 count 枚举的实际 SAT 查询为 Sv39 LOAD **60036**、Sv48 LOAD **440704**、Sv48 STORE **216116** 次；这些计数不包含诊断的组合验证查询。

若只枚举已验证可乘的**守卫域**，在每个候选分量中按完整守卫元组阻断，一次 SAT 得一个值，最后一次 UNSAT 证明完整，那么分量域大小 d_i 需 d_i+1 次查询。Sv39 的 16592 个守卫类见证可由 **308 个分量域见证**表达，预计域枚举查询为 **416 次**（60036→416，约减少 99.31%）；最大 6912 类路径对应 28 个域见证、38 次查询。这里尚未计入分解证明、建立求解器、完整状态见证及错误检查成本，也没有实现或实测这条优化路径；不能称为端到端 144 倍加速。

对两个 Sv48 场景，无条件采用各分量的 d_i+1 会得到 677 / 617 次查询，但它们对应的乘积已经被反例否定，**不能作为可交付的预计求解量**。若仅对本轮基数核对通过的路径分解，6 条耦合路径继续完整枚举，域见证量最多先估到 LOAD **122654→105615**、STORE **51638→44139**，仅约减少 13.9% / 14.5%；胖路径仍是主要成本。要取得更大的求解收益，必须先识别并保留跨组耦合，重新分组和证明；本轮尚未完成，不能承诺它们能降到几百次。

上述守卫域证明来自先完整 count 的测量，不会免费消除首次测量成本。后续优化须为固定迹／约束建立可复用的分解依据；如果每次都先完整 count 再确认乘积，首次在线生成就没有求解收益。即使守卫域已可乘，完整状态代表值仍可能需要逐类求解，故 416 也不是完整 v1 样本生成的全部求解次数。

输出方面，若理想地消除背景中枚举阶段 83% 的投影成本，其他成本不变，则整次 samples 的理论上限约为 `1 / (1 - 0.98×0.83) = 5.36×`。实际仍需具体化必要输入、构造增量并计算动态状态，因此会低于这个上限；压缩比、在线加速和离线总耗时均未测。优先试验省去完整状态重复格式化和写出的收益，比直接假设 Sv48 已能独立相乘更有依据。
### 是否采用分量分解

**按“出现在同一原约束”建图，本轮所有路径都只有一个分量，直接采用这个规则不能减少求解。** 将原断言暂时从建图中拿掉，只按守卫、上下文、片段和 ITE 依赖提出候选切分后，Sv39 LOAD 的守卫域可以相乘；Sv48 的部分路径明确不可乘。因此不能把候选切分直接替换现行枚举。

诊断保留两种图：`constraint_components` 纳入全部原断言及隐藏输入的传递连接；`components` 是只为验证提出的候选分组，`candidate_rule` 明示不含原断言。它们不是同一个结论。依赖展开按自由 BV 的位区分，别名、Extract、Concat、扩展和逐位运算保留位范围；一般算术保守使用完整操作数。守卫节点采用 `context ∧ guard`，ITE 的条件和两臂均纳入。原断言只拆最外层合取，不擅自拆析取；数组和未解释函数作为不可拆的共享依赖。这个图可能过度连接，不能由“图相连”反推数学上必然无法再分。

令完整守卫类集合为 S，各候选分量的边际域为 D_i。诊断直接在既有 count 遍历中收集投影，且检查去重守卫赋值数等于实际类数。S 总是包含于各 D_i 的笛卡尔积；当路径枚举完整且 `|S| = ∏|D_i|` 时，有限集合基数相等证明**这一条路径、这一版约束下的守卫类域**就是笛卡尔积。这比只看变量是否重叠更强，也覆盖高阶耦合。若乘积不等，诊断从乘积中找一个 S 没有的具体守卫组合，再用原约束的隔离重放求解器检查，输出 `missing_tuple_unsat=true`。不能把两两样本都 SAT 当成完整证明。

组合 SAT 检查使用各分量观察到的“守卫 + 被测位”联合见证，按字典序等间隔取至多 8 个值，每对分量检查所选值的全部组合（至多 64 组），另对超过两个分量的路径以固定种子混合 64 个全分量组合。样本数、UNSAT 数逐路径记录；这不是均匀随机抽样。Unknown 或错误沿现有错误链返回，不冒充 SAT/UNSAT。

**片段域尚未完整验证。** 本轮 `class_cap=1`，`truncated_classes` 大量非零，很多未活动守卫所引用的片段仍有其他可行值；`observed_joint_domain` 只是已访问见证的去重数，`observed_joint_product` 不是完整片段域乘积。`slice_domains_complete=false` 明示这个限制。守卫域基数证明和这些 SAT 抽样都不能证明全部片段值独立，更不能证明完整处理器状态可直接拼接。

实现分解前应先解释并消去可证明固定的共享输入，或把实际耦合的候选组重新合并，再对保留的原约束证明组合完整；不能为了得到较小分量而忽略原断言。Sv48 已有反例，不能让这些路径进入未经证明的笛卡尔积展开。诊断本身仍做完整 count，并没有实现省掉这些求解的算法。

### “每路径骨架 + 每类增量”的字段设计

使用独立的紧凑协议 `compact_schema_version=1`，展开后的每行仍是现有 sample `schema_version=1`。不能把一份完整 v1 样本当模板后只替换守卫文本：现有样本的内存、后态寄存器和返回值都来自每一类自己的同一个求解模型。

| 记录／字段 | 内容与用途 |
| --- | --- |
| 文件头 `run_id / ir_hash / config_hash / producer_version` | 固定受测模型、配置、生成器版本；版本不同不能混用证明或模板 |
| 路径骨架 `path_id / trace_hash / path_signature / mode` | 路径内符号编号的命名空间、实际原迹哈希与现有 v1 路径元数据；跨路径同号 SMT 符号不共用 |
| `base_bindings` | 一份完整、带类型和位宽的自由输入赋值，包括未测试位、CSR、读返回符号及需要的数组解释；“未测试”不等于“任意更换都合法” |
| `definitions / constraints` | 按拓扑顺序的有类型表达式 DAG，运算明确包含 BV 截断、符号扩展、ITE、数组 Select/Store 等；保留完整约束供离线求值核对。表达式编号避免反复复制字符串 |
| `state_layout` | v1 的静态字段，以及前／后寄存器、结构化返回值和 `isa_state` 中动态叶子到 DAG 的引用；寄存器、结构体、构造子、向量均保留原类型布局 |
| `memory_events` | 原顺序中的读写、提交条件、地址、数据、长度及独占写是否提交的表达式；保存 F4 的完整读保护条件 |
| 分量字典 `component_id / guard_ids / slices / values` | 守卫与片段的映射、分量取值及其完整输入补丁；只有经过组合正确性验证的分量才允许使用因子化字典 |
| 每类增量 `path_id / class_id / ordinal / guard_values / slice_values / binding_patches` | 守卫和片段值之外，必须包含所有受影响的自由输入／共享见证补丁。使用完整符号值或明确的位掩码覆盖；重叠补丁必须一致 |
| `component_value_ids / solution_index / truncated` | 可因子化时引用字典，否则保存该类自己的完整输入差量；保留类内解号、路径／类预算与 stride 元数据。不能用乘积顺序伪称原 DFS 编号 |

`binding_patches` 不能默认只含守卫测试的位。投影可行的含义是“存在其余输入”；用另一个类的未测试位填充后，可能违反 PPN 范围、地址相等、数组一致性或纯计算的附加约束。近期可以先让每类求解产生完整输入见证，只压缩重复状态；这样仍需逐类求解、具体化必要输入，但不再逐类格式化约 58KB 全状态。进一步把每类见证也分解，需要独立的组合正确性依据。

无需求解器展开的步骤：

1. 读取路径骨架，复制 `base_bindings`，应用分量字典和本类补丁；校验类型、位宽、补丁重叠和必需输入齐全。
2. 用纯求值器按拓扑顺序重算受增量影响的 DAG 节点，检查全部原约束为真。数组必须携带足以支持新地址 Select 的解释；未解释函数需要明确的函数解释或完整覆盖到的参数表。缺解释或约束为假就是数据错误，不能默认为零、继续输出或悄悄丢掉该类。
3. 由同一份求值结果重建寄存器、返回值和活动访存。按事件原顺序、小端拆字节、u64 地址回绕，沿用 v1 前内存“首次触碰”与后内存“最终触碰”规则，首次触碰为写时前值仍为 null。
4. 复用 v1 的类型序列化与 ISA 格式化规则，分配文件内唯一 sample_id，填入明确保存的 class_id、truncated 等字段，写出普通 v1 JSONL。`ret_val` 目前是原符号返回值文本，骨架须保留其既有文本语义，不把它误改成结构化 `result` 的另一种格式。

这需要一个覆盖本负载实际表达式的离线纯求值器，当前仓库尚未实现；“无需求解器”不等于“无需重新计算”。仅输出守卫／片段替换表，而不提供补充输入见证和表达式，无法保证展开为有效 v1 样本。

| 状态 | 每类如何处理 |
| --- | --- |
| 固定前态及未改写寄存器 | 只有依赖不受增量影响且赋值复用合法时才复用；后态与前态原值相同的项可继续共享 |
| 内存读结果 | PTE 读数据可能就是增量的一部分；LOAD 最终读数可能是未测试的自由输入。地址、活动条件、同址读的一致性和完整读数据都要由本类赋值重新确定 |
| 访存地址与 pre/post_memory | PPN、对齐位或保护条件改变时重新求值，重新筛选活动事件，再做首／末次覆盖；不能只修改旧地址里的数据字节 |
| 后态寄存器 | LOAD 目标寄存器、PC、异常 CSR、页表 A/D 更新相关结果可能随增量或读数据变化，必须重算其依赖；不能因“来源于同一合并路径”而复用 |
| STORE 数据、返回值与异常 | 写数据可能复用固定源寄存器，但地址、提交、更新后的页表字节、异常类型及载荷仍按依赖重算；结果构造子也不预设恒定 |
| `isa_state` 展示值 | 仅对变化的前态字段和 PMA 展示输入重新格式化，保持与同类结构化前态同源 |

### 风险与后续验收

- Sv48 的缺失组合已经是实测反例；图上省去约束所得到的独立性结论无效。两两抽样可能完全漏掉反例，类数基数核对与明确的 UNSAT 见证必须保留。
- class_cap=1 隐藏了很大的片段域；不能把本轮守卫分量的收益当成完整位片段枚举收益。
- 共享数组、同址访问、未测试位和模型补全可破坏完整输入拼接。分量守卫域可乘也不能保证各分量的独立代表模型可以合并。
- 离线求值器须复用／严格对齐既有 BV、枚举、内存和格式化语义；不支持的运算必须明确拒绝该紧凑格式，不能生成伪见证。先限定支持范围再扩展，不在本任务实现生产路径。
- 现有内存读并集及 v1 写后再读限制继续适用；紧凑格式不改变样本的适用范围，也不补出精确寄存器事件序列。
- 预计收益须分成在线求解、模型具体化、格式化／写出、离线展开四项测量。离线生成全部 v1 文件仍需写出原有体积，压缩在线输出不代表消除了这部分总工作。
- 下一步验收应先在每个已测场景抽取边界类与反例周边类：在线完整 v1 与离线展开逐字段比较，并回投原路径做成员／结果检查；最后再做全量集合与时间对照。当前没有紧凑样本实现或此项 PASS。

## F8 步骤 1：回调立即写出样本

**按用户修订后的验收：同一固定事件迹的缓冲写出与流式写出逐字段一致。** 测试覆盖类内多个解、stride=1/2/7/100、类上限与路径上限；包括最终 `truncated`、编号和全部完整状态字段。流式回调每次返回前文件已能由 SampleChecker 读取。后续又在 1/2/3/4 枚举线程下运行同一对照。

## F8 步骤 3：路径内守卫前缀并行

采用独立的 `enumeration_threads` 配置，不复用 `-T`。省略时取可用核数与 16 的较小值；显式值必须为正整数。`-T` 仍控制符号执行线程。进程内枚举工作线程共用预算，进程预算为默认线程预算与显式路径线程数的较大值，避免多条完成路径各自启动整组线程。每次调用按自己的路径线程数申请预算，路径内线程数为 1 时仍保留跨路径并发；没有因失败而切换算法。

从守卫树前序中选择前 d 个在原路径及活动上下文中正反极性均可满足的守卫，取最小 d 使 `2^d >= enumeration_threads`，守卫不足时提前结束。使用 `context ∧ guard` 生成互斥的布尔前缀，保留不可满足分区为零计数；每个线程静态领取若干前缀任务，一级使用规范布尔前缀 DFS，二级复用原来的模型引导片段 DFS。非二次幂线程数例如 3 对应 4 个前缀，最多 3 个工作线程。

`Event<B>` 的成员只依赖满足 Send/Sync 的 BV 和已有值类型；泛型工作线程的编译及 B64 编译期断言验证事件可安全跨线程。每个工作线程自建 Z3 Context、固定种子求解器并重放原事件一次，计数与导出两阶段复用该求解器。Z3 AST、Model、Context 不跨线程传递；没有新增 unsafe。每个完整样本仍使用原有隔离 Context 重放来物化，保留 stride 不改变同迹代表内容的机制，本轮没有优化这部分重放成本。

为同时保证规范类号、全局 path_cap 和跨类连续 stride，先并行遍历投影域，收集每类按 class_cap 计入的解数和截断证据；每分区预计数最多访问 path_cap 个解，不物化完整状态。协调线程检查守卫赋值无重复，按守卫树前序下的布尔位串排序，分配 class_id、路径 ordinal 和剩余全局预算；再唤醒原工作线程导出这些预算内的解。count 模式到此不再执行导出阶段。导出阶段达到本分区获配预算后立即停止，避免扫描未计划的巨大尾部。路径上限不是每分区各一份，不会因线程数增加而放大输出。

这增加了一次投影计数遍历；首条样本须等待所属路径的计数计划形成。导出阶段每个样本仍在模型回调内立即写出，没有缓存完整样本。协调线程只保留规范赋值和计数计划，计数阶段的重复类 JSON 会先释放；最终 gen JSON 的类数组和样本补写偏移仍随规模增长。该方案不承诺常量总内存，也没有实现“骨架+增量”的紧凑样本协议。

增加 `enumerate_merges_parallel_with` 接口，让生产消费者在工作线程内直接物化样本，只有文件追加和紧凑补写索引持锁。既有 FnMut 消费接口保留并由锁保护，要求消费者 Send；旧调用方无需自行处理并发。`guard_classes` 按最终 class_id 排序，sample_id 继续在共享写端分配唯一编号；样本行顺序允许不同。

结果新增 `enumeration_threads`（实际工作线程数）和 `partitions`：每项包含 `partition_id/counted_classes/counted_paths`，两种计数均按最终全局预算统计。所有分区的类数／解数之和必须等于本路径汇总；同一配置的 samples 与 count 结果也必须一致。`MERGE_ENUMERATION_PROGRESS` 报告分区计数进度，`MERGE_ENUMERATION_PARTITION` 报告分区最终预算，不使用样本文件行数作为进度。

显式的 `ISLA_ENUM_COMPONENTS=1` 且 mode=count 仍运行分量诊断专用串行参照，以保留其联合见证采集及历史测量口径；这是诊断入口的既定算法选择，不是并行错误后的替代路径。常规 samples/count 使用上述同一分区实现，包括 enumeration_threads=1。

### A：差异从哪里产生，为什么本轮不规范全部样本

代表模型的调用链为 `merge_enumeration.rs` 的 level-2 模型引导DFS → 用当前位叶子构造 `condition` → 新建独立Context和 `Solver::new_seeded(..., 0)` → 重放原路径事件 → `satisfiable(condition)`缓存Sat模型 → `Model::new` → `SamplePath::materialize`及ISA状态物化。`Model::new`只借用该缓存，没有重新随机抽样。用本机Z3的参数表实查，default/smt/qfaufbv均支持 `random_seed`，当前new_seeded的0确实写入；不能将问题归因于“未设置种子”。普通执行仍用时间种子，且生成事件迹的过程中存在无序容器。独立最小复现仅构造两个8字段结构体并调用现有merge_val，10个新进程产生10种不同的“字段→fresh符号”映射（`output/f14/hash-order/result.json`），直接确认容器遍历会改变声明编号。

三个可独立观察的来源：

1. **输入与查询顺序**：`region_merge.rs::merge_states`遍历HashSet中的局部槽、寄存器；`primop_util::merge_val`遍历结构体HashMap，影响fresh符号与AST构造顺序。原路径的Sat查询也可能影响重试和模型引导的类内叶子。两个同二进制的20路径小实验中，跨进程只有1/20路径的重放SMT文本完全相同；不能把“同一个指令场景”当成“相同事件迹”。
2. **类内叶子及完整模型未唯一化**：固定同一frame/solver/sample_path，在同进程内独立调用枚举两次，按(path_signature,class_id,solution_index)对齐完整Sample（物化时sample_id为0），4444条中274条不同；其中274条涉及vl/vtype前后态及ISA展示，11条还有内存差异。另一个小实验逐次保存重放事件和export condition：同进程20/20路径事件相同，但很多第一次叶子的condition不同；也观察到同事件、同condition、同种子下自由寄存器/内存代表仍不同。固定种子不是Z3“唯一模型”契约；尚未把后者进一步归因到Z3内部的哪一种启发式。切换 `--tastic smt` 的154条小实验仍有110条重复物化差异，不能据此提供修复。
3. **展示与编号**：`Val::write`按HashMap顺序格式化结构体，ret_val字符串的字段顺序跨进程会变，即使结构化result相同；`SampleOutputs::append`用全局原子自增分配sample_id，路径完成/并发追加次序影响编号和行顺序。编号唯一性正确，但不承诺稳定编号。

### BadRead 调查（2026-11-07）

**结论：本次四个 BadRead 都是 excluded 配置要求的路径终止，没有发现地址判断或 Sv39 执行缺陷。** 两个错误发生于后续页表的 PTE 读取，两个发生于翻译后的数据读取。逐条导出实际失败查询后，确认它们的全部可行地址都在新增设备窗口 `[0x30000000,0x30010000)`。只移除当前读取的 excluded 子句、保留全部历史断言和当前读值一致性约束，四条查询均从 UNSAT 变成 SAT。因此不是用错误文本猜测区域归属，也不是此前枚举类型登记 panic 的延续。

`partial / errors=4` 是上层统计把预期过滤与普通执行错误合并记录的结果。当前实现明确用 BadRead 表示 excluded 判死，所以这四次终止符合现有设计；若产品要求“excluded 只过滤、不报错”，应改进终止原因的表达与收集分类。**excluded 表示生成范围排除，不表示 RISC-V 架构不可读或必然产生 AccessFault。** 这两层语义不能互相代替。

#### 产生点与语义

1. `isla-lib/src/config.rs:125` 和 `isla-lib/src/memory.rs:104` 明确把 Excluded 定义为“这一段不关心”，访问时判死，不提供内容语义。它独立于 PMA 属性。`config.rs:243` 的 mmio 别名为 `readable=true`；`:256` 的 hole 为 `readable=false`。
2. 默认数组内存回调 `src/isarch/memory_model.rs:239` 把当前读值与字节数组的一致性等式，以及“不与所有 excluded 区域重叠”的约束合取后加入 solver，并返回 constrained=true。
3. `isla-lib/src/memory.rs:1240` 的 `smt_excluded_constraint` 检查实际各字节的重叠，使用模距离处理地址回绕。符号地址仍可避开 excluded 时，只收缩可行域，读取继续；当前路径被 PMA 等分支约束为只能访问 excluded 时，才整体判死。
4. `isla-lib/src/memory.rs:1037` 立即检查 SAT，UNSAT 则在 `:1038` 返回 `BadRead("symbolic address falls in excluded memory region")`。`ReadMem` 事件在 `:1040` 才加入，所以失败读取没有事件、读值或样本导出。具体地址重叠则在 `:535` 等分派点直接返回 `BadRead("excluded memory region")`。
5. `src/isarch/exec.rs:1535` 把失败交给 ErrorRecorder，`:789` 调用 `SolveCollectorState::record_error`；`:717` 对包括此 BadRead 在内的错误统一 `errors += 1`。`src/isarch/solve_summary.rs:21` 又因 errors 非零返回 partial；`:2225` 输出“执行错误”。因此这不是摘要声称四个求解器崩溃，而是四条预期过滤路径借用了错误通道。

此处 BadRead 文本本身并非通用的 excluded 归因证明：回调同时追加读值一致性，其他矛盾也可能使同一检查 UNSAT。本轮通过“保留读值等式、仅删当前 excluded 子句”的正反查询，排除了这一歧义。也不能把所有 BadRead 一律当作合法终止。

### 根因与实现

复核 F14 记录与当前 `merge_enumeration.rs`、`merge_parallel.rs`、样本物化及写出代码，三个来源仍成立：模型引导 DFS 的首个叶子没有唯一化；seed=0 不保证自由寄存器和内存的完整模型唯一；无序容器影响 fresh 符号与展示次序，并发追加影响编号和行序。本轮没有把排序或固定 seed 单独当作修复。

- `class_cap=1` 的隔离导出求解器只接收原路径约束及该类规范活动守卫赋值，不再接收 DFS 任意首个叶子的被测位赋值。投影遍历、类号、预算、stride 与截断判据继续使用既有接口。
- 按固定重放声明序依次规范全部自由有限域标量，再按固定定义序规范数组／函数的有限域可观察值；先固定自由标量，再固定读取，支持嵌套数组。复用 SMT 表达式类型推导区分数组本体与标量观察，不枚举整个数组。布尔 false 优先、位向量按无符号数序最小化（保留任意位宽）、枚举按声明成员序取第一个可行值。先尝试最小值和唯一性证明，再对确有自由度的位向量从高位到低位做 SAT 选择。规范标量逻辑放在 `merge_representative.rs`，复用原有模型读取、保存点及增量 SAT 接口，没有引入 Z3 优化器或新的 unsafe。
- 局部槽、寄存器及结构体合并按已有 Name 序处理，结构体和符号构造子的文本也按此顺序显示，消除哈希遍历对变量分配与文本的影响。规范约束只存在于每个代表自己的隔离求解器，不覆盖 ISA 入口状态，也不修改原执行求解器。
- 仅使用 v1_jsonl 后端且本会话每个枚举类只输出第 0 个解时，正常收尾按 `(path_signature, class_id)` 排序并连续编号；相同路径／类在不同 clause 重复时以除 sample_id 外的完整内容打破平局。保留已有文件前缀及编号，新追加部分从原最大编号之后开始。内存只存文件偏移索引，每次读写一个完整样本，临时排序文件位于输出文件旁并在完成后删除。运行中仍即时写出，最终文件稳定性在正常收尾后成立。

samples v1 字段、版本、成员绑定语义保持不变。`class_cap>1` 的类内 DFS 继续使用原模型引导选择。多后端组合和字节预算后端继续使用原同源追加编号，不承诺这些容器文件的原始字节顺序；本轮固定语料验收使用单独的 v1_jsonl 导出。`class_cap=1` 仍是每类一个见证，不代表穷举该类全部具体位组合：本场景 `truncated_classes=1182`、`truncated_paths=0`。

# 路径合并：区域化推演合并（统一设计，2026-11-05）

本文件是现行唯一设计，取代此前"基础版 + 评审补丁"的叠加写法。前半部分讲原理，后半部分是给实现者（Codex）的详细规范。行号来自 `.worktree/isla-enumerate` 分支 `feat/postprocess-enumeration` 的 94b2cfb 之后版本，实现时以当前源码为准。

## 1. 目标

符号执行时放开分叉，再靠路径合并把"对称性强、相似度高"的分支（典型是 PTE 的 V/R/W/X/U/A/D 等位字段逻辑）在汇合处合成一条路径，压低路径数；后处理再用笛卡尔积展开。最终目的：由符号求解得到页表应有的形状，输出结构化数据给后续测试模板用。

## 2. 现状证据（单次 60 秒 Sv39 LOAD 观测，不是定论）

- 合并尝试 736 次、成功 0 次；原因：臂内函数调用被拒 336、`range_subset` 的不纯二元运算 168，越界跳转 670（与调用拒绝一一对应，多为错误候选的伴随失败）。见 `agents/execution_stats/result-20261105-sv39-60s.md`。
- 根因：分支臂由独立小解释器 `simulate_diamond_arm` 推演，它不支持调用、返回、`have_exception` 边和限制记账；汇合点由"菱形/三角 + pc+64 窗口"启发式确定。
- 访存路径上没有预算限制；PTE 位没有被 Sail 改写成 ITE，`pte_is_invalid` 的 `|`/`&` 在 IR 里是真实的短路分支。

## 3. 总体架构

只保留一个解释器，给它加"推演模式"。符号分支处把两臂各推演到汇合点（函数内直接后支配点），用 ITE 合成；区域内的嵌套分支递归合并。散落在解释器各处的分叉、副作用和事件，不逐点打补丁，而是收口到三个关口。

### 3.1 三个关口
1. 分支决策口：所有会分叉或建检查点的位置（符号 Jump、Monomorphize、操作数重试、`symbolic_length`、特殊分叉、限额采样）在碰检查点或 fraction 之前先过同一个函数。普通模式行为不变；推演模式下，仅当另一侧在全部外层条件下 Unsat 才走单边（Unknown 视为拒绝），存在内层区域则递归合并，否则拒绝。
2. 副作用分类：每个原语只分类一次——纯、读状态、写状态、可能分叉。有原语没有分类则测试失败；取代手写白名单（现缺 `zeros`、`lteq_bits_u`，多元原语一律被拒）。
3. 事件出口：所有迹事件走同一个出口；推演时按保存点层缓冲，最外层区域提交成功后才发布。解决"事务丢弃非 SMT 事件"。

### 3.2 求解器保存点栈
用保存点栈取代单层事务：保存日志缓冲偏移、invalid 标志、符号表、模型、性能状态；内层提交并入父层，只有最外层提交才发布。`next_var` 当前不回退，需处理。内层补 Assert 会使父事务失效，需要专门规则。

### 3.3 区域的静态分析（按函数，复用 `isla-lib/src/ir/ssa.rs` 的 CFG）
- 异常检查边按极性剔除（`have_exception` 的真边，或 `@not(have_exception)` 的落空边），不按 goto 形状匹配；Arbitrary、Exit、return 后 goto 等所有终止形态指向统一虚拟出口，再求直接后支配点。
- 区域 = 入口到汇合点之间的可达节点集；出区域、无汇合点、含回边（对该子图做 SCC/DFS，不能只看 pc 区间）则静态拒绝。
- 区域可以止于函数返回，此时合并后的返回值是 ITE。这覆盖"纯谓词返回合并后的布尔值"，不需要另做函数摘要。
- 区域内局部变量用静态保守活跃性（含绕行、回边、重定义、Loc 读改写）判定"区域之后不再用"，合并处丢弃。
- 实测依据（`pte_is_invalid`，141 条指令）：指令 9→138、32→135、54→132 等，OR 链是汇合点各异的嵌套区域；普通图的后支配点都是 141（函数出口）。

### 3.4 合并语义
- 值：以分支条件作 ITE。
- 寄存器写：按条件保留，保持写入顺序；被调函数内部禁止写寄存器和 let（含 `have_exception`），入口深度的寄存器写与现状一致，嵌套不得重设许可深度。
- 寄存器读：采用"访问足迹取并集"。只在一臂被读取的寄存器，在合并路径上视为被读过。适用范围见 §6。只在一臂惰性读取的未初始化寄存器，其新鲜符号提升到合并帧，不与"未初始化"做 ITE（两臂的初值是同一个未知量，状态仍精确，仅读事件不精确）。
- 合并记录（作为副产物）：每次成功合并记录函数、区域 pc→join、条件符号、被合并值的自由输入符号；单臂寄存器读同时记录其保护条件符号。后处理据此得到"被合并区域的输入"作为枚举对象（来源 b）。自由输入需展开定义依赖（`simplify.rs` 附近）。

### 3.5 回滚与安全网
自适应模式下，任何拒绝都回滚到最外层保存点，退回普通分叉。强制模式见 §4。

## 4. 局部合并策略（配置）

目标：定制过的 Sail-RISC-V 模型可以按局部强制开启、关闭或自适应合并；调试局部不影响其他部分；强制失败立刻报错退出，避免无谓等待。

- 位置：`--execution-limits-config` 指定的 TOML，与 `region_fork_limits` 相邻，新增 `[[execution_limits.merge_policy]]`：
  - `mode = "force" | "adaptive" | "off"`；
  - 选择器二选一：`function = "<Sail 原名>"`（加载时 zencode），或源码区域（与 `region_fork_limits` 同一套 file/start_line/start_column/end_line/end_column，复用 `SourceRegion`、`strict`、`ir_sha256` 与 `verify.py`，Sail 模型变动时区域坐标可检查）。
- 全局默认：不带标志为 off；`--path-merging` 为 adaptive。"全局 off + 局部规则"即为只调试某处。
- 匹配单位：规则匹配"两侧都可行的符号分支点"；函数规则只匹配该函数自身函数体内的分支，不含被调函数。
- 优先级：区域规则 > 函数规则 > 所在推演区域继承的策略 > 全局默认。同一精度的冲突规则在加载时报错。强制臂内被调函数里的分支，默认继承该臂策略，除非有显式规则。
- 嵌套冲突：自适应区域内遇到显式 off → 外层回滚并分叉；强制区域内遇到显式 off → 致命错误，信息写明两处位置。
- 强制失败必须是整个运行级别的终止，而不是单路径错误（Isla 默认把 `ExecError` 记在单条路径上继续跑别的路径，且 `--timeout` 之后进程不会退出）：打印一条结构化诊断（规则、函数、分支 pc 与源码位置、拒绝原因标签、触发拒绝的指令位置），用专用非零退出码经 `process::exit`/abort 退出，不依赖工作线程 panic（其他线程会继续存活）。需有测试验证进程快速退出。
- 加载期校验：函数名在 IR 中找不到 → 错误；区域不匹配任何分支 → `strict` 下错误；`force` 规则所在区域无后支配点或含回边 → 执行前报错（静态区域分析已有结果，零额外成本）。
- 统计：`ISLA_STATS=1` 下按规则报告尝试数、成功数与拒绝原因，用于局部调试。

## 6. 已知限制与适用范围（须写入代码注释）

- 寄存器读取取并集：合并路径的主迹里，只在一臂读取的寄存器被视为读过。对"前置状态"和 JSON 访问足迹没有影响；若要研究读写顺序或需要逐条精确迹，则该合并路径的迹不可信。注释要写在合并提交处，并写入合并记录的文档，提醒后续使用者。
- 升级路径：给每个事件附带所在臂的保护条件（guarded events），消费方在模型下求值即可恢复该路径的精确迹。这需要改动全部迹消费方（JSON 输出、足迹分析、simplify、公理化部分），是单独的项目，本次不做；本次只记录单臂读取及其保护符号，保证以后可重建。
- 含内存读取的区域按设计被拒，所以 `pt_walk` 读 PTE 与递归那一层仍会分叉；合并发生在标志位逻辑内（`pte_is_invalid`、`pte_is_non_leaf`、`update_PTE_Bits` 条件，可能还有 `check_PTE_permission`）。调用方随后对合并后的布尔值分叉，原先每种无效原因各一条路径，变成有效/无效两路。
- 静态无环不代表无递归：`pt_walk` 自递归，由共享推演预算与内存读取拒绝约束。
- 纯函数摘要复用（按函数与实参形状缓存）属组合式符号执行路线，作为后续选项，不属本次。
- 合并策略的启发式（按求解代价决定是否合并，参考 Kuznetsov 等 2012；引用前需核实）本次不做，策略钩子保留为"自适应 = 总是尝试"。

## 10. 集成规格：带条件约束协议（guarded constraints，2026-11-05）

背景：C1–C4 合并后的独立评审（第 9 条）指出，单边执行、嵌套合并、断言三者的协议不兼容：单边可行路径仍补 Assert 会被 C3 判为事务失效；旧合并流程在内层提交后补等式同样使父层失效，随后读取整理口因深度≠1 而 panic；C4 允许的纯原语（如 `pow_int`）会产生新鲜变量等式，却被 C3 拒绝。统一采用以下协议（状态合并文献中的标准编码）。

### 10.1 协议
1. Z3 的 push/pop 只承载分支臂条件 `g`，臂内的可满足性查询据此看到条件。
2. 推演层内产生的每个 `Assert`（`assume`、单边分支事实、纯原语的新鲜变量等式）进入该层缓冲；层提交时，对每条以 `Implies(g, c)` 重放进父层。变量声明不加条件。
3. 嵌套自然组合：每次提交先用本层条件包装缓冲再交给父层，最外层看到 `g1 → (g2 → c)`。
4. `invalid` 标志只保留给真正不支持的操作，不再因 `Assert` 而置位。
5. 写规格前先核实：`define_const` 如何降级；现有日志缓冲是否已在臂的 pop 之后重放臂内定义——若是，则把同一重放扩展到断言。

该规则带来的简化：不再需要"单边可行就不补断言"的特例（该事实只是一条冗余的带条件约束）；内层断言不再使父层失效；读取整理只在最外层发布时做，内层只追加，深度≠1 的 panic 消失；C3 与 C4 的 `pow_int` 冲突消除。

### 10.2 推论
- 死臂：臂返回 `Dead` 或臂内断言失败时，提交 `g → false`，沿用另一臂状态，不做 ITE（剪枝而非拒绝合并）。
- 唯一可行方案不是分叉：门在每个位置（Jump、取值唯一的 Monomorphize、长度已确定的重试）推广为"只有一个可行方案则直接走它"；Unknown 仍拒绝。
- 寄存器读取上提：区域入口处提升惰性初始化寄存器的新鲜符号，旧合并流程的提交后等式因此不再需要，直接删除而不是移植，并整体退休 `try_merge_diamond`。
- 内层拒绝：回滚到最外层保存点并在该处分叉；各分叉路径上的内层分支在普通模式下各自再尝试合并，损失的只是工作量。任一嵌套内的 Force 规则失败即为致命错误。
- 事件标注：提交时给缓冲事件打上本层条件，成本极低；发布时按并集语义压平，带条件的读取存入合并记录。
- 过渡：F1 在推演模式下拒绝 `assume`/`assert`，集成时由带条件重放取代该拒绝；入口深度的 `Exit`/`Arbitrary` 仍为拒绝；断言失败变为死臂。

### 10.3 避免重复无效尝试
- 静态预筛：按函数构建传递效应摘要（C4 的类别 + 调用图，递归保守处理）；区域内含内存访问或 WritesState 调用则在推演前静态拒绝。
- 否定缓存：拒绝原因与上下文无关时，以（函数，分支 pc）为键缓存。

### 10.4 验证
- 差分判据工具：同一 IR 分别跑分叉模式与合并模式，用 Z3 检查合并结果 ≡ ∨(路径条件_i ∧ 返回值_i) 并检查覆盖。

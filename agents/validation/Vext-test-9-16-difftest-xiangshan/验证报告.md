# Isla `make solve` → XiangShan DiffTest 验证结果

## 范围与结论

本目录固化了本次对 XiangShan 的验证输入、运行产物和可复核 PoC。

- 原始 `make solve` 结果：101 个 JSON，共 19,908 个状态。
- 其中 `Retire_Success(())` 状态：10,799 条，均已生成 ELF 并运行 XiangShan DiffTest。
- DiffTest 失败：89 条。
- 已确认 RTL bug 复现：9 条 PoC，均为同一个已公开问题 [OpenXiangShan/XiangShan#6039](https://github.com/OpenXiangShan/XiangShan/issues/6039)（`vsetvl` 的 `rd=x0` 导致核失去前进）。
- 新发现、可单独报告的 RTL bug：0 条。

| 失败类别 | PoC 数 | 判断 |
|---|---:|---|
| `vmerge.vim` | 19 | `vstart!=0` 时 NEMU 的非法指令与 XiangShan 的继续执行差异；RVV 许可，不是 RTL bug |
| `vmerge.vvm` | 20 | 同上 |
| `vmerge.vxm` | 35 | 同上 |
| `vmv.s.x` | 2 | 同上 |
| `vmv4r.v` | 2 | 同上 |
| `vmv8r.v` | 2 | 同上 |
| `vsetvl` | 9 | 真实 RTL 活性错误，但与 #6039 重复 |

对前六类共 80 条，所有初始状态均满足 `vstart!=0`。RVV 规范允许实现对某些无法由该实现自行产生的非零 `vstart` 抛出非法指令；因此 NEMU trap、而 XiangShan 继续执行，不构成 ISA 违例。

## 独立复核

以 `case-086` 为例，在 `../difftest-xiangshan` 中使用 XiangShan 的 `emu`，不连接 NEMU：

```sh
timeout 35s xiangshan/build/emu \
  -i ../isla/agents/validation/difftest-xiangshan/poc/case-086/program.elf \
  --no-diff
```

该程序在 35 秒内没有提交、异常或 `GOODTRAP`，被 `timeout` 终止。触发共同条件为：`vstart=0`，执行合法的 `vsetvl rd=x0, rs1!=x0, rs2=*`，随后核无法继续提交。这正是 #6039 已公开的问题范围；本目录 PoC 仅提供额外的寄存器与 `vtype` 覆盖。

批量 DiffTest 的执行环境、统计过程和完整失败表见仓库根目录的 `Report.md`。

# 路径合并端到端能力测试（Sail 小模型）

目的：用最简的 Sail 模型验证"**内层合并失败不连累外层**，且合并后形状正确"。Rust 单测（`isla-lib/src/executor/tests/nested_merge_failure_tests.rs`）用合成 IR；这里用真实 Sail 源码经 `isla-sail` 编译成 IR，再用 `isla-execute-function`（`--path-merging --traces`）执行并数路径，作为端到端验收。

## 要验证的形状（外层 a∈{a1,a2,a3} × 内层 z∈{b1,c2,c3}）
- 外层三条臂 a1、a2、a3 只在常量取值上不同，**可以合并**。
- 内层三条臂：`b1` 与 `c2`、`c3` 留下的**具体值不同**（不可合并），`c2`、`c3` 留下**相同的值**（可合并）。
- 完全不合并：3 × 3 = **9** 条路径。
- 期望合并结果：内层只能部分合并（`c2`+`c3` 合成一个 `c`，`b1` 单独），外层三条臂合并时**对内层留下的各片段按兼容性分组**：结果为 **2** 条路径 `{ a·b1 , a·c }`（`a` 表示外层三个取值已合并）。**外层汇合点不是只能有一种情况，而是随内层的结果而定。**

## 场景表（骨架，由 Codex 审核、补全、增删）
| 编号 | 场景 | 不合并 | 期望合并后路径数 | 说明 |
| --- | --- | ---: | ---: | --- |
| S1 | 外层 3 × 内层 {b1,c2,c3}（c2、c3 同值，b1 不同） | 9 | 2 | 本文件开头的核心用例 |
| S2 | 外层 3 × 内层全部同值 | 9 | 1 | 对照：内层可全合并，整体合成 1 条 |
| S3 | 外层 3 × 内层三个值互不相同 | 9 | 3 | 内层完全不可合并，外层仍合并：3 条（内层 3 种） |
| S4 | 三层嵌套，仅最内层部分失败 | — | 待定 | 各层独立 |
| S5 | 被调用函数里的内层失败，调用方合并成功 | — | 待定 | 函数调用边界 |
| S6 | 内层失败发生在外层汇合点自己（外层汇合后仍存活的变量各臂不同） | — | 待定 | 失败只局部，不连累更外层 |

每个场景：先跑 `--path-merging` 关闭得到"不合并"的路径数作基线，再开启合并，断言合并后路径数、以及每条路径的守卫语义（对每个输入取值，合并结果的返回值与不合并一致：用同一组具体输入逐一执行比对，或用 `--model` 取模型）。递归与平铺两种合并策略（`[execution_limits.path_merge] strategy = "recursive" | "flat"`）都要跑。

## 运行
```
python3 test/path-merge/test_nested_merge_local_failure.py --output <输出目录>
```
需要：`sail`（带 `isla-sail/plugin.cmxs`）、`target/<profile>/isla-execute-function`。
